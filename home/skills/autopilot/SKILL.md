# autopilot

仕様は人間と合意済みの前提。実装は自分で行わず、裏の `autopilot-run` に引き継いで最後まで自走させる。
人間に通知が届くのはあなたがターンを終えたときだけなので、任せた後は終わるまで黙っていることが価値になる。

コマンド: `autopilot-run`。状態はすべて worktree 直下の `.autopilot/` にある。

## 1. 任されたら

1. `.autopilot/brief.md` を書く。実装担当はこの会話を知らないため、合意した仕様や受け入れ条件をこれだけで作業できるようにまとめる。
   - 目的 / 仕様と受け入れ条件 / 会話で決めたこと / 任せる判断（担当の裁量でよいこと）/ 関連 Issue・PR
2. `autopilot-run` をシェルで起動する。実装担当には自分と同じエージェントを指定する。レビューは自動で他のエージェントが担当する。
   ```bash
   autopilot-run --impl claude
   ```
   - 実装と修正の賢さは `--level` で選ぶ。既定は `high`。文言・設定値・依存の更新のような小さく機械的な仕事は `--level standard` にする。迷ったら既定のままにする。
   - push・PR を伴わない試運転は `--local` を付ける。
   - 実装は済んでいて、レビューだけ回したい（例: 前回 `何も commit されなかった` で終わったが、PR はある）ときは `autopilot-run --impl claude --from review` にする。実装を飛ばし、今のブランチの PR のレビューから始める。
   - モデルは段階ごとにホストの models.yaml で決まっている（`autopilot-run models` で確認できる）。自分で選ばない。
   - レビュー担当やモデルを人間に指定されたときだけ、`--reviewers agy,copilot` や `--impl claude:MODEL` のように渡す。
3. 「任せた。終わったら呼ぶ」とだけ返してターンを終える。

## 2. 終わって起こされたら

`.autopilot/status` と `.autopilot/result.md` を読み、人間に返す。

- 結果（done / needs-human / failed）と PR の URL
- 主な判断と、見送ったレビュー指摘
- 人間の判断が必要なこと（あれば選択肢と推奨を添える）

## 3. 自走中に話しかけられたら

`autopilot-run status` で実行中か確認してから対応する。

| 人間の意図 | 対応 |
|---|---|
| 進捗を知りたい | `.autopilot/status` と `.autopilot/run.log` の末尾、`git log` を読んで答える |
| 軽い追加指示（止めなくてよい） | `.autopilot/inbox.md` に追記する。裏の担当が次の区切りで読む |
| 方針を変えたい・じっくり議論したい | `autopilot-run stop` で止めてから話す。まとまったら brief.md を更新して再び起動する |

**実行中はコードを書き換えない。** 同じ worktree を並行で触ると壊れる。書き換えが要るなら必ず止めてからにする。

## 禁止

PR のマージ、Issue・PR のクローズ、既定ブランチへの push。マージは常に人間が行う。
